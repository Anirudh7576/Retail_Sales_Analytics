1. Purpose

   The purpose of the data model is to define the structure of the data warehouse, identify the relationships between tables, and provide a scalable schema that supports efficient reporting and analytical queries.

2. Data Warehouse Schema
   
   Snowflake is used as the enterprise cloud data warehouse. Data is loaded into the RAW schema from the source systems. Business transformations are performed in the SILVER schema, and the final curated data is stored in the GOLD schema for reporting and analytics.

3. Fact Table

   FACT_SALES stores all sales transactions generated by the business. It contains measurable business metrics such as sales amount, quantity, discount, profit, and tax, along with foreign keys that reference the dimension tables.

4. Dimension Tables

    DIM_PRODUCT : Contains detailed information about the products sold by the company, such as product name, brand, price, and product attributes.
    DIM_CATEGORY: Contains the category information for each product, such as Electronics, Clothing, or Home Appliances.
    DIM_SUBCATEGORY: Contains the subcategory information for each product, providing a more detailed classification within a category.
    DIM_GEOGRAPHY: Contains geographical information about where the sales transactions occurred, such as country, state, city, and region.
    DIM_PAYMENT: Contains information about the payment methods used by customers, such as Credit Card, Debit Card, UPI, Cash, or Online Banking.
    DIM_CUSTOMER: Contains customer information, such as customer ID, customer name, gender, age, contact details, and customer location.
   
5. Star Schema Justification

    A Star Schema is selected because it simplifies analytical queries, improves query performance, reduces the complexity of reporting, and is optimized for Business Intelligence tools such as Power BI. The fact table stores measurable business events, while the dimension tables provide descriptive information used for filtering and analysis.

6. Primary Keys

   DIM_PRODUCT: product_id
   DIM_CATEGORY: category_id
   DIM_SUBCATEGORY: subcategory_id
   DIM_GEOGRAPHY: geography_id
   DIM_PAYMENT: payment_id
   DIM_CUSTOMER : customer_id
   DIM_DATE : date_id

7. Foreign Keys
   
   product_id, category_id, subcategory_id, geography_id, payment_id, customer_id, date_id.

10. Power BI Considerations

    The star schema is optimized for Power BI because it simplifies relationships between tables and improves report performance. Dimension tables are used as slicers and filters, enabling business users to analyze sales by product, category, geography, payment method, and time.
